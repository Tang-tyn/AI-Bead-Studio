## 1. HomePage（首页）详细设计

### 1.1 页面目标

用户进入 App 后的**项目中枢**。完成两件事：
1. 快速查看/继续已有项目
2. 发现社区灵感和推荐内容

### 1.2 与 CreatorPage 的分工

| | HomePage | CreatorPage |
|------|----------|-------------|
| 定位 | 项目浏览 + 发现灵感 | 创作工具入口 |
| 核心操作 | 继续编辑项目、浏览社区 | AI创作、照片转图纸 |
| 用户意图 | "我要继续上次的工作" | "我要开始新的创作" |
| 入口卡片 | 小尺寸、快速跳转 | 大尺寸、引导式 |

**HomePage 不放大型创作入口**。创建新项目走 CreatorPage Tab。

### 1.3 用户操作流程

```
用户打开 App（闪屏后）
   │
   ├─ 有历史项目 → 看到最近项目列表 → 点击项目卡片 → 进入编辑器
   │
   ├─ 无历史项目 → 看到空状态引导 → "去创作"按钮 → 切换到创作Tab
   │
   └─ 浏览推荐 → 看到社区作品 → 点击作品卡片 → 进入作品详情
```

### 1.4 信息层级

```
L1: 页面标题 "AI拼豆" + 搜索图标
L2: 快速操作区（小卡片横排）
    - "继续创作" → 跳转 CreatorTab
    - "新建项目" → 跳转 CreatorTab/ImageImportPage
L3: 最近项目（横向滚动列表）
    - 项目缩略图 + 名称 + 最后编辑时间
L4: 推荐作品（瀑布流预览，2列）
    - 社区热门作品的缩略图
    - "查看更多" → 跳转 SquareTab
```

## 2. CreatorPage（创作页）详细设计

### 2.1 页面目标

用户的**创作起点**。提供两条清晰的创作路径，引导用户开始创作。

### 2.2 与 HomePage 的功能区分

- **HomePage**：侧重"浏览和管理已有项目"，快操为辅助
- **CreatorPage**：侧重"开始新创作"，是完整的功能入口

用户在 HomePage 点击"新建项目"可以跳到 CreatorPage，也可以直接跳到 ImageImportPage。
这个决策权在 HomePage 的快速操作区 → 点击"新建项目"时直接走 router.push(ImageImportPage)，跳过 CreatorPage。

### 2.3 用户操作流程

```
用户切换到创作Tab
   │
   ├─ 想AI风格化照片 → 点击"AI风格创作"卡片
   │   → AICreatePage (Phase 5)
   │   → 上传照片 → 选择风格 → AI处理 → 预览 → 确认 → 进入编辑器
   │
   └─ 想直接转图纸 → 点击"照片转图纸"卡片
       → ImageImportPage (Phase 2 → 3)
       → 选择照片 → 配置参数 → 转换 → 预览 → 确认 → 进入编辑器
```

### 2.4 信息层级

```
L1: 页面标题 "创作中心"
L2: AI创作入口（大卡片，上半屏重点）
    - 图标 + 标题 + 描述

    - 操作按钮
L3: 照片转图纸入口（中等卡片）
    - 图标 + 标题 + 描述
```

### 2.7 AI创作入口的关键设计决策

**为什么用大卡片 + 风格标签，而不是简洁的两按钮？**

1. **AI 是旗舰功能**：需要足够的视觉权重吸引用户尝试
2. **风格选择前置**：减少跳转后的操作步骤，提升转化率
3. **扩展能力**：未来增加风格时，只需在标签行添加，不改变布局
4. **教育用户**：通过标签展示 AI 能力，即使用户不点也能感知功能

### 2.8 风格标签交互

- 默认不选中任何标签 → "开始AI创作"按钮为次按钮样式（描边）
- 选中某个风格 → 按钮变为主按钮样式（填充），引导点击
- 支持多选？→ 不支持，AI每次生成一种风格
- 未选择风格直接点击 → 跳转到 AICreatePage，在那边选择

## 3. PatternEditorPage（图纸编辑器）初步设计

> 虽然编辑器在 Phase 4 实现，但它是整个 App 的核心页面。
> 提前设计可避免架构返工，也为 Canvas 组件设计提供输入。

### 3.1 页面目标

用户编辑拼豆图纸的核心工作区。需要：
- 高精度 Canvas 网格渲染
- 高效的颜色选择与填色
- 流畅的手势操作
- 不打断创作流程的工具切换

### 3.2 用户操作流程

```
从 ImageImportPage 或 AICreatePage 进入
   │
   ├─ 查看图纸 → 双指缩放/平移浏览
   │
   ├─ 编辑格子 → 选择颜色 → 点击填色
   │            → 长按吸色 → 自动切换画笔颜色
   │            → 点击填充 → 同色区域全部变色
   │            → 点击橡皮 → 清除格子颜色
   │
   ├─ 撤销/重做 → 点击撤销按钮 / 双指轻点撤销
   │
   ├─ 查看材料 → 点击材料按钮 → 弹出底部面板
   │
   └─ 导出 → 点击导出 → 选择格式 → 保存
```

### 3.3 信息层级

```
L1: 顶部信息栏（半透明，悬浮在 Canvas 上）

    - 撤销/重做
L4: 底部颜色面板（可收起/展开）
    - 当前调色板的颜色色块横排
    - 滚动查看所有颜色
```

### 3.6 手势设计

| 手势 | 工具模式 | 行为 |
|------|----------|------|
| 单指点击 | 画笔 | 该格填充当前选中颜色 |
| 单指点击 | 橡皮 | 该格清空 |
| 单指点击 | 填充 | 该格及相邻同色格全部填充 |
| 单指点击 | 吸色器 | 获取该格颜色并自动切换回画笔 |
| 长按 (500ms) | 任意 | 临时切换吸色，获取颜色后恢复原工具 |
| 双指捏合 | 任意 | 缩放画布 (0.25x ~ 4.0x) |
| 双指拖动 | 任意 | 平移画布 |
| 双指轻点 | 任意 | 撤销 (快捷手势) |

### 3.7 Canvas 渲染策略

```
视口裁剪优化：
  Canvas 只绘制当前可视区域内的格子
  视口 = { x: panX, y: panY, w: screenW/zoom, h: screenH/zoom }

绘制流程：
  1. 计算当前视口覆盖的格子范围
  2. 遍历可见格子，fillRect 绘制色块
  3. 如果 showGridLines → strokeRect 绘制网格线
  4. 如果 showSymbols → fillText 绘制颜色编号

性能目标：
  - 29×29 格 → < 16ms 绘制 (60fps)
  - 58×58 格 → < 16ms 绘制 (60fps)
  - 100×100 格 → < 32ms 绘制 (30fps, 可接受)
```

### 3.9 撤销/重做机制

```
数据结构：
  undoStack: BeadCell[][]    ← 最多50步
  redoStack: BeadCell[][]    ← 每次新操作时清空

操作流程：
  用户操作前 → 快照当前所有格子状态 → push undoStack
  用户操作后 → 更新格子 → 清空 redoStack
  用户撤销   → 当前状态 push redoStack → pop undoStack → 恢复
  用户重做   → 当前状态 push undoStack → pop redoStack → 恢复

快照策略：
  - 只快照变化的部分（差异快照），不是整个网格
  - 或者快照整个网格但限制步数（简单实现，先这样做）
```

## 5. 设计约束（强制）

> 所有页面开发必须遵守以下约束，违反即为不合格。

### 5.1 设计先行原则

```
任何新页面开发必须按以下顺序执行：

① 页面布局图    → ASCII 或手绘，标注区域功能
② 组件树        → 列出所有子组件及层级关系
③ 状态设计      → 列出 @State 变量、数据来源、更新时机
④ 数据流        → 画出 ViewModel → Service → Model 调用链路

以上 4 项完成后，才能开始写 ArkTS 代码。
```

### 5.2 UI 质量标准

| 标准 | 要求 |
|------|------|
| 布局 | 卡片式布局，不允许简单组件堆叠 |
| 信息层级 | H1 > H2 > H3 三级标题清晰 |
| 留白 | 页面边距 16-20vp，组件间距 ≥ 8vp |
| 颜色 | 100% 使用 $r('app.color.xxx') 引用，不允许硬编码 |
| 字号 | 100% 使用 fp 单位，不允许硬编码数字 |
| 图标 | 优先 SymbolGlyph（已验证支持的），禁止正式页面使用 emoji |
| 深浅色 | 必须同时在浅色和深色模式下验证 |
| 动画 | 页面切换、按钮点击、加载状态必须有动画 |

### 5.3 禁止事项

| 禁止 | 说明 |
|------|------|
| 禁止 Demo/测试风格 UI | 所有页面按最终发布质量设计 |
| 禁止 Phase/开发阶段 文字出现 | 如"此页面将在Phase X实现" |
| 禁止 emoji 作为正式图标 | 仅开发期临时占位 |
| 禁止硬编码颜色 | 必须用 $r() |
| 禁止不设计直接编码 | 先输出 ①~④ 再写代码 |
| 禁止随意创建新组件 | 先查 view/components/ 是否有可复用的 |

### 5.4 页面开发检查清单

每个页面开发完成后自查：

```
□ 布局图与实际代码一致
□ 组件树正确映射到代码结构
□ 所有颜色使用 $r('app.color.xxx')
□ 所有字符串使用 $r('app.string.xxx')
□ 浅色模式正常显示
□ 深色模式正常显示
□ 无硬编码数字（间距/字号/圆角）
□ 有加载态和空态处理
□ 点击有反馈动画
□ 无 emoji 作为功能图标
```
